# Agent workflow

> Scope: read by OpenAI Codex CLI only. Claude Code (and any other agent) follows `CLAUDE.md`
> instead -- the two files are not interchangeable and this one's "Luna"/"Workspace access" content
> does not apply outside Codex.

- For substantial PanGloss work, use the `agent-handoff` skill at high reasoning effort and delegate concrete, bounded research or implementation tasks to Luna as the normal path. Up to two Luna agents may receive `Workspace` access under the standing repository disclosure authorization.
- Resolve architectural questions with a Luna research handoff before implementation. Before build-heavy delegation, measure live physical memory, commit headroom, CPU load, and active procgov/Cargo trees. Permit up to two concurrent managed builds when both 19 GB job caps fit with ample headroom; increase beyond that only from fresh measurements and keep all Rust work inside `rust/tools/pg.ps1`.
- Before changing an FST threshold, refusal, retry, or containment mechanism, classify the evidence explicitly as **correctness/representability**, **production readiness**, or **resource containment**. Do not use a readiness Error to avoid a contained stress attempt, and never use a larger limit to excuse incomplete or unproven output. The controlling contract is `docs/superpowers/specs/2026-08-23-stress-grammar-construction-and-production-admission.md`.
- **Never re-derive a decision another module makes — call it, or extract it.** Measured: four of seven attempts in one session were reverted, three of them for this. Each reproduced a condition the emitter already decides by reading its diagnostic text, and each was a strict superset that refused grammars which compile. A helper named `*_candidates` / `*_candidate_rules` names a candidate SET, not a decision — the emitter turns it into a refusal only under gates the caller cannot see. If the fact is not exposed, factor it out of its owner so both read one computation (`crate::emit::eager_route_refuses_unbounded_closure` is the worked example). Give a published fact a one-way gate asserting only that a claimed refusal really refuses. And check the SEAM before the condition: the same condition failed with 7 test failures as a `CapabilityPredicate` and passed with 0 at `backend_selection`'s per-strategy refusal seam.
- **Build the differential measurement before the change.** `envelope_agrees_with_compiler_gate` reports agreement and BOTH divergence directions, which is the only reason those four reverts cost one build cycle each and shipped no regressions — one of them changed no behaviour and failed no test, and was visible only in the before/after counts. A gate that counts only what you closed cannot see what you broke. Stage the assertion as a ratchet (`FaithfulnessRequirement::NoMoreThan`) rather than all-or-nothing, which on a non-empty inventory asserts nothing.
- **Reach for `pg.ps1 -Mode check` first, `-Mode test` last.** Suite EXECUTION is ~100s; the round-trip cost is linking 105 integration test targets plus 32 examples in pg-foma alone. `check` (`cargo check --all-targets`) type-checks test and example code without linking — the question a green `-Mode build` cannot answer and twice did not. `-Mode quick` adds `--lib --bins` unit tests. Narrow COMPILATION with `-Package`/`-TestTarget`; `-Filter` narrows execution only. Test modes no longer stop at the first failure (`-FailFast` opts back in): a count from a run that stopped early is not a count.
- The primary agent must personally inspect every delegated diff and claim, resolve integration issues, and rerun the authoritative verification. Never treat a Luna result as trusted without review.
