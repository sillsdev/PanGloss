# WordMaker differential harness

The supported reference is LibLCM `d564a719b1cce16c25ebea53a537393cb757f5d1`, Machine `4d9b454d42a0da35e058641a65596339a79d115b`, ICU 70.1 and Unicode 14.0. The harness confines ICU to version 70, initializes SLDR offline and records the actual ICU and Unicode versions. Build from those source revisions; never label another build with these revisions. `reference-icu70.json` was produced by this harness in a fresh process using that context. It is required by the parity integration test and preland, which also exercise missing-reference and altered-boundary negative controls. Rust CI runs the integration test; release gates rebuild and run the live oracle and compare all WordMaker cases and provenance with the pinned reference.

Build with `dotnet build rust/dotnet-harness/WordMakerParity -p:LibLcmRoot=/path/to/liblcm -p:MachineRoot=/path/to/machine -p:DisableGitVersionTask=true`. Set `LIBLCM_REVISION` and `MACHINE_REVISION` to the actual checked-out revisions and ensure ICU 70 is discoverable. Run `python3 rust/dotnet-harness/WordMakerParity/smoke.py /path/to/WordMakerParity.dll` to run a fresh process and compare all WordMaker cases to the reference. To refresh the reference, run the DLL with `cases.json` and an output path, inspect the changes and run the Rust parity test.

The oracle loads LDML through the pinned writing-system mapper, which decodes exemplar sets with ICU. Each case records the SHA-256 of its LDML; the comparator also verifies the decoded Rust additions, all case names, run profile hashes, exact word slices and UTF-16 boundaries. Chapter/Verse ranges in the corpus are code points, converted to UTF-16. Machine results are reported separately: its punctuation, apostrophe, hyphen, abbreviation and URL behavior intentionally differs from WordMaker. Input text is never normalized.
