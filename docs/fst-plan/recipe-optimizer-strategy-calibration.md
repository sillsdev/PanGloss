# Recipe optimizer strategy calibration

This report is generated by `cargo test -p pg-foma --test recipe_optimizer_calibration -- --nocapture`.
The fixture is deterministic: candidate IDs, families, admissible lower bounds, exact objectives,
seed, budgets, and evaluator usage are all fixed in the integration test. The evaluator implements
the real `CandidateEvaluator` contract and returns confirmed synthetic evidence from known ground
truth; it does not replace any search strategy.

## Strategy decisions

The adaptive selector is exercised directly. Small spaces qualify for exhaustive search. The
medium and weak-pruning spaces use DiverseBeam when exhaustive admission fails without a strong
topology signal. The pruned-large and strong-pruning spaces use BranchAndBound, where admissible
bounds and exact incumbents make pruning observable. The misleading-cheap-fidelity case stays on
the conservative beam path: cheap pilot cost alone is not evidence that fidelity predicts the
final objective.

Branch-and-bound is chosen over dynamic programming because recipe candidates are not a fixed
optimal-substructure state graph: constraints, family/signature diversity, and confirmation costs
are candidate-specific, while the evaluator contract exposes complete candidates and admissible
bounds. DP would require inventing a state equivalence and transition algebra that the optimizer
does not have. Branch-and-bound preserves the existing candidate/evaluator boundary and can certify
pruning only from exact incumbent objectives.

Successive halving remains disabled. There is no calibrated relationship in these fixtures between
cheap fidelity and final objective quality; enabling it would turn an unvalidated pilot estimate
into a pruning decision. A future calibration must establish predictive error bounds first.
