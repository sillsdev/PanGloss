# Recipe optimizer strategy calibration

This report is generated by `cargo test -p pg-foma --test recipe_optimizer_calibration -- --nocapture`. The test uses finite, fully enumerable reduced recipe fixtures. Candidate IDs, families, signatures, admissible lower bounds, exact objectives, seeds, budgets, and evaluator work are fixed. Exhaustive search supplies the ground-truth winning ID and scalar objective; approximate coverage means finding that same optimum, not merely returning some confirmed candidate. Regret is `approximate objective - exhaustive objective`.


`operations` is deterministic search accounting (`generated + expanded + pruned`). `work` is deterministic evaluator work, not host wall time. The distinction matters: branch-and-bound still accounts for examining/pruning candidates, but reduces expensive evaluations from 120 to 2 and evaluator work from 1,192 to 12. Every seeded beam run is replayed byte-for-byte in the test.

The aligned fixture models a strongly informative admissible lower bound: even width 4 finds the optimum. The threshold fixture places fourteen admissible lower-bound decoys ahead of the optimum: widths 4 and 8 miss it with regret 18, while widths 16 and 24 recover it on all three seeds. Width 16 is therefore the smallest tested width that covers both the aligned and threshold fixtures, using 26 work units versus 106 at width 24 on the threshold case. The weak-signal fixture is deliberately legal but adverse: the optimum has a valid yet unhelpful bound, so every tested width through 24 misses it with regret 8. This is the checked-in reason that width 16 is a measured compromise, not a correctness guarantee.

## Pilot calibration

Production's deterministic sampling function is applied to a fixed heterogeneous 32-cost population over five seeds:

```text
PILOT size=4 population_p95=94 median_abs_error=21 max_abs_error=38
PILOT size=8 population_p95=94 median_abs_error=12 max_abs_error=38
PILOT size=16 population_p95=94 median_abs_error=12 max_abs_error=12
```

Eight candidates improve median p95 error from 21 to 12 without doubling pilot work again. Sixteen materially improves the worst case but not the median. The default cap remains 8 as the exploration-cost compromise; the p95 estimate remains evidence for strategy selection, not a hard runtime promise. For spaces smaller than eight, all candidates are sampled.

## Selector and reserve calibration

The checked selector boundary is:

```text
RESERVE fraction=0/1 search_coverage=130/130 confirmation_available=30 confirmation_required=40 confirmed=false
RESERVE fraction=1/8 search_coverage=130/130 confirmation_available=30 confirmation_required=40 confirmed=false
RESERVE fraction=1/4 search_coverage=120/130 confirmation_available=40 confirmation_required=40 confirmed=true
RESERVE fraction=1/2 search_coverage=80/130 confirmation_available=80 confirmation_required=40 confirmed=true
SELECTOR exhaustive_fraction=1/2 finite_reserve_fraction=1/4 pilot_cap=8 beam_width=16 strong_topology=branch-and-bound weak_topology=diverse-beam successive_halving=disabled
```

Each `RESERVE` line above is produced by running the production `optimize_with_evaluator` loop over 13 candidates that each cost 10 elapsed units, so `search_coverage` is elapsed the real search actually spent, not a re-derivation of the allocation in the test. That distinction matters: until the loop enforced `Budget::search_elapsed()`, `reserve` was read exactly once (in `choose_strategy_with_policy`) and the sweep could consume the whole deadline, so these same numbers were arithmetic the test performed on itself and would have held even with no reserve enforcement anywhere in the compiler.

The deterministic two-phase workload has 160 total work units, 130 units of useful search demand, and 40 units of finalist-confirmation demand. Zero and 12.5% reserves spend 130 on search and leave only 30, so confirmation fails. Both 25% and 50% reserves confirm, but 25% preserves 120/130 search coverage versus 80/130 at 50%; it is the smallest tested successful reserve. Separately, the exhaustive selector admits `N_static * pilot_p95` only when it fits within one half of post-pilot search time. On the boundary fixture (`N=32`, p95=2, elapsed=160), no reserve selects exhaustive; reserving 40 units selects beam because the exhaustive estimate would consume more than half of the remaining search allowance. Therefore finite production runs use 25% as the measured reserve default with `--reserve-ns`; an unlimited deadline needs no numeric reserve. This reduced workload calibrates policy allocation, not real-language wall-clock variance.

When exhaustive admission fails, a strong-pruning or compositional topology selects branch-and-bound; a weak topology selects diverse beam. The 120-candidate fixture validates the former against exhaustive ground truth. Branch-and-bound is preferred to dynamic programming because the current registry exposes complete candidates, not a proven optimal-substructure state algebra.

Successive halving remains disabled. Neither fixture establishes a predictive relationship between a cheaper fidelity and final HC-confirmed objective quality. Enabling it would turn an unvalidated estimate into a rejection decision.

## Scope of the calibration

These reduced fixtures calibrate policy mechanics and expose both favorable and adverse admissible bounds. They do not estimate real-language build-time distributions; the four promoted grammar report supplies that complementary production evidence. The numbers justify the current pilot cap, beam width, half-budget exhaustive threshold, 25% finite reserve recommendation, and third-strategy selector, but they do not prove regret bounds for an unseen grammar.
