## Ordering deviation from the plan, and why

The plan's Task 1 asks for the differential census — including
`compiler_succeeds_production_rejects` / `compiler_succeeds_production_admits` — **before**
`PartialMorphemeFacts` or `assess_completed_fst` exist. There is no honest way to populate those
two columns at that point: with no admission function to call, both would be structurally
constant, and this repo's own rule is that a control which cannot act must not return quietly.

So Tasks 2 and 3 were landed first. Neither changes any behaviour: Task 2 adds a validated
read-only grammar fact, and Task 3 adds a pure function that nothing calls. The differential census
then measures the real admission decision against the real compile outcome across every fixture ×
every strategy, and that census passes **before** Task 4/Task 5 wire the decision into artifact
creation and selection. The property the plan's ordering exists to guarantee — the measurement
exists before the behaviour-changing change — is preserved exactly; only the placement of the
no-op commits moved.

### Conformance work is staged in this repo, not committed upstream

The plan's Task 7 names three files inside the `machine` submodule:
`machine/conformance/edge-cases/morphotactic-attribute-breadth/words.yaml`,
`machine/conformance/obligation-triage.tsv`, and `machine/conformance/gate-obligations.tsv`.
None of the three was edited, for two independent reasons established by inspection:

- **Both TSVs are generated, not hand-authored.** `gate-obligations.tsv`'s first line reads
  `# GENERATED by hc-conformance --write-gate-obligations`, and `hc-conformance.exe --help`
  confirms `--gate-obligations` / `--write-gate-obligations` recompute and rewrite them from
  `engine-gate-inventory.tsv`, `interface-witness.tsv` and `fieldworks-producibility.tsv`. Editing
  rows 40-43 by hand would produce a ledger the next generator run reverts, and would claim
  evidence no severance sweep produced.
- **The generator only reads its own `--fixtures` root.** A fixture added under this repo's
  `conformance-staging/` is invisible to `hc-conformance --write-gate-obligations`, so no staged
  fixture can move a row in those ledgers. Moving them genuinely requires the fixture to live in
  `machine/conformance`, which means a `sillsdev/machine` commit plus a submodule pin bump — and a
  pin bump to an unpushed commit would break every other worktree and CI on this branch.

So the discriminating cases were authored instead as a staged fixture,
`conformance-staging/edge-cases/final-template-partial-discriminators/`, which this repo's own
documented fixture lifecycle (`.claude/skills/conformance-grammars/SKILL.md`) treats as the
zero-reshaping precursor to exactly that upstream PR. It runs unconditionally in the default suite,
so the four arms are witnessed here now.

**What that leaves undone, explicitly:** the two obligation ledgers still read `NotEvidenced` /
`Open` for `NonPartialRuleProhibitedAfterFinalTemplate:{Blocked,Control}` and
`NonPartialRuleRequiredAfterNonFinalTemplate:{Blocked,Control}`. Closing those four rows is
follow-on work with a fixed recipe: graduate the staged fixture into `sillsdev/machine`
(`conformance-framework`), then re-run
`hc-conformance.exe --repository-root machine --write-gate-obligations` and
`--write-coverage-traceability`, then bump the pin. Scaling that down was not this branch's call to
make silently, which is why it is named here rather than omitted.

## What the differential census measures, and why it has no before/after delta

`rust/crates/pg-foma/tests/envelope_agrees_with_compiler_gate.rs` now reports four columns over

| `envelope_admits_compiler_fails` | the pre-existing too-lax direction |
| `compiler_succeeds_production_rejects` | compiled, then refused publication |
| `compiler_succeeds_production_admits` | compiled, and publishable |

The census deliberately calls `witnessed_coverage::compile_with_backend_for_measurement` (renamed
from `compile_with_backend` for exactly this reason), which asks production admission nothing. So
the two new columns cannot be moved by Task 4's or Task 5's wiring: `assess_completed_fst` is a pure
function of the grammar, and the compile column comes from a path that never consults it. The
census therefore has no before/after delta by construction — and that is the property worth having,
because any movement in it IS a regression rather than an expected consequence of the change.

The two pre-existing columns keep their **exact named inventories** rather than the plan's
`FaithfulnessRequirement::NoMoreThan` ratchet. Named inventories are the stronger assertion: a
`NoMoreThan` count admits swapping one divergence for another, and this gate already named every
row before this branch touched it. Downgrading it to a count would have been a regression in the
measurement.

The production columns assert no magic total. What they assert is exact and cannot be satisfied
vacuously:

- the two columns **partition** the compile successes (sum equals the compile-success count);
- **no** partial-free observation is refused (an over-refusal fails by name);
- **no** partial-bearing observation is admitted (a dropped refusal fails by name);
- at least one observation is admitted, so the census can still see an over-refusal;
- a rejection is required whenever the claimed scope actually contains a partial-bearing fixture,
  and the run prints `partial-bearing observations in this scope` either way rather than letting a
  scope with none read as a clean pass.

## What the typed refusal deliberately does not carry

`CompletedBuildError::NotProductionReady { strategy, health }` carries no `CompletedBackendBuild`,
no payload bytes and no payload fingerprint. That is the point: there is nothing in the error a
caller could reassemble, and a unit test asserts the rendered error does not contain the
fingerprint of the payload the measurement half actually produced.

The measurement half is exercised directly in the same test, so the gate cannot be mistaken for a
compiler that simply fails on these grammars:

```
compile_completed_backend_for_measurement(&partial_grammar, TunedSurfaceProbed, &attempt)
    -> Ok, non-empty payload
compile_completed_backend(&partial_grammar, TunedSurfaceProbed, &attempt)
    -> Err(NotProductionReady { strategy: TunedSurfaceProbed, health })
       health.admission()                        == NotProductionReady
       health.admission_by_class().representability == WithinLimits
```

The same grammar with the partial marker removed still returns a completed build, so the refusal is
attributable to the one variable.

## Where the gate actually sits

Four places could plausibly hold a production-readiness gate. Only three of them can act, and the
fourth was deliberately left alone.

| Seam | What it does | Why here / not here |
|---|---|---|
| `completed_build::compile_completed_backend` | compiles once for measurement, then refuses | The decisive one. No payload, no fingerprint and no `CompletedBackendBuild` appear in the error, so there is nothing to reassemble — an absence, not a filter. |
| `worker.rs`'s child output | typed `SelectedNotProductionReady`, one frame | Typed apart from `SelectedCompileFailed` because it is a verdict about a result that WAS built. A test reads the frame stream and requires the second frame to be absent. |
| `RuntimeEvaluation` → optimizer ranking | a blocked candidate contributes no ranking row | Cannot win and cannot reach the Pareto frontier, because it is not in the input to either. |
| `selection.rs::select_plan` | **nothing** | Its own module doc records that no production path calls it. A gate there would compile, run, change no behaviour and enforce nothing — the inert-control shape this repo refuses. |

Two details in the third row are load-bearing:

- **The recomputation invariant survives.** `BackendOptimizationReport::validate` re-derives the
  frontier and winner from the *serialized* candidates and requires them to match. Filtering only
  in the optimizer would have made that recomputation disagree, so `CandidateReport` gained
  `production_blocks_publication` (`#[serde(default)]`, so a report written before it still parses)
  and `BACKEND_REPORT_SCHEMA_VERSION` went 4 → 5. Both sides now filter on the identical predicate.
- **One owner for the comparison.** `RuntimeEvaluation::production_blocks_publication` is the single
  place a `production_health` becomes a publication verdict, and everything threading the fact
  onward reads it rather than comparing against `Severity::NotProductionReady` by hand.

The "could not look" cases are fail-closed throughout, not defaulted to publishable: a candidate
that never reached a completed FST gets a `BuildProcessFailed`/`NotProductionReady` report, and an
admission that could not be decided at all becomes `CompletedBuildError::PartialFactsUnavailable`
rather than a quiet admission. An empty `HealthReport` reads as `WithinLimits`, which is exactly the
silence this repo's `CLAUDE.md` refuses, so no path here produces one to mean "unknown".

## Why the partial policy is READINESS and not CannotRepresent — measured, not assumed

`Readiness` claims the grammar is representable and merely unshippable. That is a claim about
**recall**: every FST strategy must still propose the analyses HermitCrab confirms on a
partial-bearing grammar, including the ones that exist *only because* a rule is partial. Nothing
measured that when the class was chosen.

The gap was concrete rather than theoretical. The first version of
`final-template-partial-discriminators` pinned both final-template **refusals** and contained no
word whose parse depended on a partial rule succeeding — precisely the shape an under-proposing
backend would lose in silence. `pg-foma`'s
`every_backend_proposes_the_analyses_that_exist_only_because_a_rule_is_partial` was written to
measure it and ran RED against that fixture, reporting the emptiness directly rather than as an
argument:

```
staging:edge-cases/final-template-partial-discriminators: this gate needs at least two words
whose parse DEPENDS on a partial rule, or a backend that silently under-proposes on partials
would pass it; found []
```

The gate identifies partial-dependent words **structurally**, not by hardcoding strings: it loads
the fixture twice, clears every `AffixProcessRuleDef.partial` and `LexEntryDef.partial` in the
second copy, and keeps the words that HermitCrab analyses in the first and not at all in the
second. That is the same "must parse, and only because the rule is partial" property a manual
red-on-revert demonstrates, expressed as a standing assertion instead of a one-off.

It then requires `faithfulness_coverage::observe_fixture_containment` to report `Held` for **each**
of the three strategies on that fixture. `NotAttempted` fails it deliberately: an unmeasured backend
cannot support the weaker classification, and the aggregate `faithfulness_coverage_gate` report
cannot answer this on its own — it is keyed by `(CharacteristicKind, EmissionStrategy)` and names
only one example fixture per failed pair, and there is no `CharacteristicKind` for partiality, so
this fixture's rows are pooled with every other fixture exhibiting the same kinds. The per-fixture
entry point is what isolates the question.

### The partial-dependent positives

`pilfbvb` (`pil` + `finalTemplateB` + `mrGate2Partial`) parses **only** because the rule is partial:
`NonPartialRuleProhibitedAfterFinalTemplate` would otherwise refuse an ordinary rule applied after a

| `mrGate2Partial` | `pilfbvb` | `pilnbvbfb` |
|---|---|---|
| `partial="true"` | `PIL+FINTAGB+GATE2PARTIAL` | no analysis |
| `partial="false"` | no analysis | `PIL+NONFINTAGB+GATE2PARTIAL+FINTAGB` |

One attribute, two opposite flips, both oracle-confirmed. This is the word an under-proposing
backend would lose in silence, and it is now in the fixture the containment gate reads.

`nibgi` is the second, and it exercises a different arm: Branch C's root is not partial, so
`templateZ` is *applicable* by POS, but its one mandatory slot requires a final segment in `ncOnlyK`

- **Not a representability limit of the construct.** `plan-composed` proposes it, so the construct

Raising it is what keeps the branch landable without hiding anything; the const's doc comment now
names the exact word, the three constructs, the two backends, the fact that `plan-composed`
proposes it (so the construct is representable and this is an emitter gap, not a limit), that

previously held are gone because `main`'s `abfecf90` changed
`segment-natural-class-table-binding`'s own ground truth, so the membership turned over rather than
the backlog growing.

not own, or changing `pg-rules`/`pg-parse`. HermitCrab and the C# oracle agree that `daknagafa`
parses; the emitters are behind, and the acceptance test is the faithfulness gate in BOTH
directions — the six rows must clear while over-generation stays at 0 and neither of
`envelope_agrees_with_compiler_gate`'s two exact named inventories moves.

### Root cause, diagnosed and NOT patched

Measured per backend on the two Branch A words:

| word | plan-composed | tuned-surface-probed | templated-underlying-tokens |
|---|---|---|---|
| `dakfa` (one template) | proposes `[9,0]` | proposes `[9,0]` | proposes `[9,0]` |
| `daknagafa` (template → loose → template) | proposes `[9,1,2,0]` | proposes `[]` | proposes `[]` |

A total miss, not a multiplicity gap, and only on the two-template word — which localizes it to the
SECOND template application.

**One shared cause, and it is a topology limit rather than a refusal bug.** `emit::emit` (backing
`TunedSurfaceProbed`) and `emit::emit_underlying_templated` (backing `TemplatedUnderlyingTokens`)
build the same lexc skeleton: `TmplDispatch` → prefix slots → root → one loose-suffix opportunity →
`G{gi}Join` (a one-of union over the template group's members) → `OuterSfx` (a second loose-suffix
opportunity) → `#`. That admits **at most one template application per word**, with loose ordinary
rules strictly before and/or strictly after it. There is no arc back from "after a loose rule" into
`G{gi}Join`, which is exactly what `daknagafa` needs — the mirror of `SynthesisStratumRule.cs`'s
`ApplyTemplates` → (changed) → `ApplyMorphologicalRules` → (not final) → `ApplyTemplates` recursion.

The composite machinery cannot cover for it: `emit::structural_candidate_rules_for_root` admits only
`is_structural_rule` shapes (circumfix, reduplication, dropping-allomorph) into that search, and all
three rules here are plain `CopyFromInput` + `InsertSegments` suffixes, so the search never attempts
the word. `TemplatedUnderlyingTokens` has no composite machinery at all.

`morphotactics::MorphotacticIndex` DOES model the recursion correctly (its own engine fact 4), so the
knowledge exists in the crate — but there is no existing "does this word need a second template
pass" decision in `emit.rs` or `morphotactics.rs` to call or extract. Closing the gap means adding a
bounded re-entry arc to two whole-grammar lexc compilers together with a termination argument
mirroring the engine's own "recurse only if the template actually changed the word" rule. That is a
redesign of the emitted topology, not the call-the-owner pattern, so it was deliberately left
undone here rather than attempted and reverted — the failure mode `CLAUDE.md` records four times
over.

## Remaining limitations

Named rather than omitted, because each one is something a reader could otherwise reasonably assume
this branch closed.

1. **Partial-bearing grammars are intentionally FST-production-ineligible, and that is not a
   compiler failure.** Every FST strategy compiles them under containment and every one refuses to
   publish. If that ineligibility is later judged too broad, the change belongs at
   `production_admission::assess_completed_fst` — the single owner — and not at any of its callers.

2. **Iterative epenthesis remains an HC-Rust divergence.** `pg-parse`'s
   `tests/csharp_port_rewrite.rs:411` is still `#[ignore]`d: `syn_epenthesis` is structurally
   Simultaneous-shaped whatever mode a rule declares, so composing two Iterative epenthesis rules
   over-fires relative to the C# oracle. Untouched by this branch.

3. **The five-grammar evidence is local, not CI-reproducible.** `five_language_backend_reports_gate`
   is `#[ignore]`d and needs gitignored private corpus exports. Its new fact-derived
   production-status assertion is therefore only as verified as the local `census`-profile run
   recorded above, and CI cannot re-derive it. That same run also exposed three pre-existing
   failures in the OLD tests in that file — a stale sena expectation, three timeouts, and two
   process aborts — none from this branch and all detailed above.

7. **Two backends cannot propose a word that needs template → loose rule → template.** Measured, not
   suspected: `daknagafa` is proposed by `plan-composed` and by neither `tuned-surface-probed` nor
   `templated-underlying-tokens`, because both build a lexc skeleton admitting at most one template
   application per word. It is a shared topology limit in `emit::emit` and
   `emit::emit_underlying_templated`, not a refusal bug and not a partial-recall miss; the full
   diagnosis, including why the composite machinery cannot cover it, is above. The faithfulness
   ratchet sits at 6 to hold it visibly rather than silently, and closing it needs a bounded
   template re-entry arc with a termination argument mirroring
   `SynthesisAffixTemplatesRule.cs`'s own "recurse only if the template changed the word". Left as
   its own piece of work; the acceptance test already exists.

4. **The two upstream obligation ledgers still read `NotEvidenced`/`Open`** for both arms of both
   final-template gates. They are generated files inside the `machine` submodule, and moving them
   requires graduating the staged fixture upstream — see the conformance section above for the exact
   recipe. This branch adds the witnessing fixture; it does not move the ledger.

5. **Comment hygiene is not at zero, and none of the remainder is this branch's.** After fixing the
   seven violations this branch introduced, nine remain: eight inherited from `main`'s tip
   (`abfecf90`) in `pg-foma/tests/cross_table_root_respelling_gate.rs`, `pg-foma/src/emit.rs` and
   `pg-rules/src/surface_probe.rs` — verified untouched here with
   `git diff --name-only abfecf90 --` returning empty for all three — plus one throwaway signature
   dumper deleted before landing. Two of the eight are `cross-reference-claim`s, which the policy
   says must become a link or a test rather than be reworded; compressing the other six would have
   discarded real rationale another commit wrote deliberately. Left for whoever owns that change.

6. **`selection.rs::select_plan` is deliberately NOT gated.** Its own module doc records that
   nothing in production calls it, so a production-readiness filter added there would compile, run,
   change no behaviour, and enforce nothing — the inert-control shape this repo's `CLAUDE.md`
   refuses. The gate lives where a result can actually escape: `completed_build`
   (no artifact, no payload, no fingerprint) and the runtime evaluation's selection path.
