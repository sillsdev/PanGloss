# Phonological distance vs. hand-authored G2P + Soundex for spell-checking Phase 3

## Findings

### 1. Phonetic hashing (Soundex, Metaphone, Beider-Morse): mechanics, English-specificity, and information loss

- **Soundex** (Odell & Russell, US Patent 1,261,167 (1918) and 1,435,663 (1922)): keep the first letter; map remaining consonants to six numeric codes (`AEIOUWYH`→0 is dropped, `BPFV`→1, `CSKGJQXZ`→2, `DT`→3, `L`→4, `MN`→5, `R`→6); collapse adjacent duplicate codes; pad/truncate to a fixed 3-digit code. This is an *equivalence-class hash*: every input collapses to one of a small fixed number of buckets. [west-penwith.org.uk/misc/soundex.htm](https://west-penwith.org.uk/misc/soundex.htm), [genealogyintime.com](http://www.genealogyintime.com/GenealogyResources/Articles/what_is_soundex_and_how_does_soundex_work_page2.html).
- **Metaphone** (Philips, 1990) and **Double Metaphone** (Philips, 2000) are English-pronunciation-specific consonant-mapping rules; Double Metaphone adds a primary+secondary code pair and some non-English loanword patterns. **Metaphone 3** (Philips, 2009) is reported (by the algorithm's own author's documentation, secondary-summarized) to reach ~99% accuracy on English words/names, versus ~89% for Double Metaphone — a **measured, but author-reported, not independently peer-reviewed** number. [aspell.net/metaphone](http://aspell.net/metaphone/), [datablist.com](https://www.datablist.com/learn/data-cleaning/double-metaphone).
- **Beider-Morse Phonetic Matching (BMPM)** targets Ashkenazic/Sephardic Jewish surnames across ~16 languages (Czech, Dutch, English, French, German, Greek, Hebrew, Hungarian, Italian, Latvian, Polish, Portuguese, Romanian, Russian, Spanish, Turkish), via a 5-stage pipeline: (1) ~200 rules identify candidate source language(s) from spelling patterns; (2) language-specific rules (40–130+ rules depending on language) map to an "exact phonetic value"; (3) ~200 additional cross-linguistic rules produce an "approximate phonetic value" capturing known sound interchanges (e.g. unstressed Russian o/a); (4) a Hebrew-specific stage handles transliteration ambiguity; (5) matching against a database. [stevemorse.org/phoneticinfo.htm](https://stevemorse.org/phoneticinfo.htm), [avotaynuonline.com](https://avotaynuonline.com/2008/07/beider-morse-phonetic-matching-an-alternative-to-soundex-with-fewer-false-hits-by-alexander-beider-and-stephen-p-morse/). **No quantitative precision/recall numbers were found** in the primary Avotaynu article for BMPM vs. Daitch-Mokotoff Soundex — only qualitative, example-based claims ("eliminates a large number of false positives" but "misses semantically-, not just phonetically, driven Anglicizations like Silber→Silver"). This is an **assertion**, not a measured result.
- **General information-loss argument** (my synthesis, but directly motivated by Zobel & Dart's own stated rationale for building Editex — see §2): all of the above hash arbitrarily many distinct spellings onto one discrete bucket key. Two segments one distinctive feature apart (e.g., a fully-voiced vs. partially-devoiced obstruent) either fall in the same bucket (in which case *all* other featural distance is thrown away — a stop and a completely different-place stop can be equated) or in different buckets (in which case they get zero credit for closeness, identical to a maximally different segment). There is no notion of "how much" two segments differ, only "same bucket or not." This is fundamentally a hash, not a metric.

### 2. Real phonetic/phonological distance metrics

- **Editex** (Zobel & Dart, "Phonetic String Matching: Lessons from Information Retrieval," SIGIR'96, pp. 105–110): an edit-distance variant where substitution cost between two letters is 0 if identical, 1 if the letters fall in the same hand-authored "sounds-alike" letter group (e.g. `{c,k,q}`, `{g,j}`), else 2; also adds "tapering" (higher weight for mismatches earlier in the word). This is explicitly a hybrid of Soundex-style grouping *and* a real distance metric (graded cost, not a hard bucket). Zobel & Dart's own motivation for building it was that Soundex-style equivalence-class hashing has poor precision/recall in IR-scale name matching. A **measured result** surfaced via search-engine secondary summary (I could not extract the original SIGIR PDF's text directly — flagged below): Editex reportedly achieved the best result among methods tested, precision ~17.4% averaged over 11 recall levels, evaluated against a 30,000-distinct-surname dataset. **I was unable to fetch/read the primary PDF directly** (`goanna.cs.rmit.edu.au` is unreachable from this environment, and other PDF fetches failed to extract text) — this number should be treated as reported-by-others-about-the-paper, not independently verified by me. [ResearchGate abstract](https://www.researchgate.net/publication/2521448_Phonetic_String_Matching_Lessons_from_Information_Retrieval), [ACM DL](https://dl.acm.org/doi/10.1145/243199.243258).
- **ALINE** (Kondrak, "A New Algorithm for the Alignment of Phonetic Sequences," ANLP-NAACL 2000): decomposes each phone into articulatory features — multivalued continuous-scale `[0,1]` features (place, manner, height, backness) plus binary features (nasal, voice, aspirated, retroflex) — each feature carries a **salience weight** (relative importance), and dynamic-programming alignment sums weighted per-feature differences into an overall similarity/distance score. This is a genuine **weighted-feature substitution-cost model**, structurally the closest published analogue to "derive substitution cost from a segment's own feature vector." Kondrak's follow-up, "Identifying Cognates by Phonetic and Semantic Similarity" (NAACL 2001), uses ALINE distance for cognate detection. **I could not extract quantitative accuracy numbers from either PDF** (both fetches returned unreadable binary/compressed content) — flagged as unverified. [aclanthology.org/A00-2038.pdf](https://www.aclweb.org/anthology/A00-2038.pdf), [aclanthology.org/N01-1014.pdf](https://aclanthology.org/N01-1014.pdf).
- **PMI-induced segment distances** (Wieling, Nerbonne, et al., dialectometry): rather than a universal feature table, this line of work *empirically learns* substitution costs from a corpus — align dialect-atlas pronunciation transcriptions with Levenshtein distance, compute pointwise mutual information between aligned segment pairs, re-align using the new PMI-derived costs, and iterate to convergence. Frequently-corresponding segment pairs get low substitution cost; rarely-corresponding pairs get high cost. **Measured result** (via secondary summary of Wieling & Nerbonne's papers, PDF not independently re-verified by me): "strong correlations were found between the induced phonetic distances and acoustic distances" for Dutch and German dialect data. [let.rug.nl/~nerbonne PDF](https://www.let.rug.nl/~nerbonne/papers/Wieling-MN-CLIN-final-2011-Nov-15.pdf). Note the contrast with ALINE/PanPhon: this is a *data-driven* cost matrix, not a *symbolic-feature-derived* one — conceptually adjacent to, but distinct from, what PanGloss's `unif_closure` would give (which is symbolic/authored, not corpus-learned).
- **PanPhon** (Mortensen, Littell, Bharadwaj, Goyal, Dyer, Levin, COLING 2016): maps 5,000+ IPA segments to 21 articulatory features and provides a `Distance` class computing feature-edit-distance, with substitution cost as either the Hamming distance between two segments' feature vectors or a weighted per-feature edit cost. The paper's stated contribution is that such linguistically-motivated feature representations outperform one-hot/character-level baselines on NER- and G2P-related tasks. **I could not extract the specific quantitative comparison numbers** from the PDF (extraction failed both attempts) — the "outperforms" claim is reported here at the level the aclanthology abstract states it, not independently verified in full by me. [aclanthology.org/C16-1328](https://aclanthology.org/C16-1328/). PanPhon is architecturally the closest published precedent for exactly the pg-featstruct `feature_lanes`/`SymbolBits` design (§ code citations below): a per-segment feature-lane vector used to compute graded substitution cost, rather than a hash bucket.

### 3. Deriving an error model from an owned grammar (the central, least-precedented question)

- **Theoretical substrate for PanGloss's own cascade already exists in the literature**: Kaplan & Kay, "Regular Models of Phonological Rule Systems" (Computational Linguistics 20(3), 1994) established that ordered phonological rewrite-rule systems (and Koskenniemi's two-level formalism) denote regular relations realizable as a **cascade of FSTs**, each comparing two successive derivation levels. [aclanthology.org/J94-3001.pdf](https://aclanthology.org/J94-3001.pdf). This is the direct theoretical ancestor of `pg-rules/src/cascade.rs`'s `LinearRuleCascade`/`PermutationRuleCascade`/`CombinationRuleCascade`, and of `pg-rules/src/rewrite.rs`'s `synthesize`/`analyze` pair (`rewrite.rs:982`, `:1446`) — i.e., PanGloss already *is* a faithful instance of exactly the machinery this paper is about. But Kaplan & Kay's paper itself is about generation/recognition, not spelling correction or error modeling — it supports the substrate, not the error-model idea directly.
- **Composing an edit-tolerance transducer with a morphological/two-level transducer** is a documented technique: Oflazer, "Error-tolerant Finite-state Recognition with Applications to Morphological Analysis and Spelling Correction" (Computational Linguistics 22(1), 1996) composes a Levenshtein-style edit-tolerant recognizer with a two-level Turkish morphological transducer so that error-tolerant recognition, morphological analysis, and spelling correction happen in one composed search rather than as separate stages. **I was unable to extract the PDF's actual text** (two fetch attempts both returned unreadable binary/compressed content) — I only have search-engine-summary-level confirmation that this composition exists and what problem it solves, not verified detail on exactly which level (lexical vs. surface) the edit tolerance is inserted at, or Turkish accuracy numbers. This should be flagged as **found-but-not-verified-in-primary-text**. [aclanthology.org/J96-1003.pdf](https://aclanthology.org/J96-1003.pdf).
- **HFST/weighted two-level composition** (Lindén & Pirinen, "Weighting Finite-State Morphological Analyzers using HFST tools"; Pirinen, work on Omorfi): describes composing a weighted lexicon transducer with a weighted error-rule transducer via weighted intersecting composition, again at the level of general architecture description from search summaries rather than independently verified primary-text detail. [researchgate.net/publication/228912097](https://www.researchgate.net/publication/228912097_Weighting_finite-state_morphological_analyzers_using_hfst_tools).
- **Rule inversion specifically as a spelling-correction mechanism, or modeling writer competence errors as failure-to-apply/over-application of a specific phonological rule (spelling the underlying form where the surface form was expected, or vice versa): I found no direct precedent.** This is the honest, explicit gap the prompt anticipated. What exists is adjacent, not on-point:
  - Generic linguistics commentary that spelling errors can be "phonologically motivated" (e.g., unstressed-vowel neutralization obscuring an underlying contrast) appears in secondary/pedagogical sources, not a specific citable primary NLP paper on rule-misapplication-as-error-model. This should be read as **background linguistic common ground**, not a design precedent.
  - Statistical, non-phonological spelling correction for morphologically rich, low-resource languages does exist and reports real numbers: a trigram-based statistical error corrector for isiZulu (agglutinative, low-resource, Bantu) reports 89% language recall, 84% error recall, 85% language precision, 88% error precision on non-word error correction — but this is a **corpus n-gram model, not a phonological-rule-inversion model**, and the paper explicitly notes candidate corrections must be filtered against a corpus word list because the agglutinative morphology otherwise overgenerates non-words. [meteck.org/files/CorrectorisiZuluISTAfrica18.pdf](http://www.meteck.org/files/CorrectorisiZuluISTAfrica18.pdf). This shows the *problem* (naive edit-based correction overgenerates for morphologically rich languages) that grammar-derived correction would need to solve, without itself being an instance of the grammar-derived solution.
  - **Conclusion for this sub-question, stated plainly**: "use the grammar's own phonological rule cascade, run in reverse, as a spelling-correction generate-and-test mechanism" and "derive substitution costs from a language's own natural-class/unifiability structure rather than a universal feature table" are **not things I found already published**. They are a reasonable, well-motivated *extension* of Kaplan & Kay's cascade-of-FSTs result, Oflazer/HFST's precedent for composing error-tolerance with a two-level transducer, and PanPhon/ALINE's precedent for feature-derived (rather than hashed) substitution cost — but the specific synthesis (grammar-owned feature system as the cost source, instead of a universal or hand-authored one) appears to be PanGloss's own idea, not reheated prior art. State this explicitly in any design doc that cites this research.

### 4. Grapheme-to-phoneme (G2P) in low-resource/field-language settings

- **Epitran** (Mortensen et al., "Epitran: Precision G2P for Many Languages," LREC 2018) supports 60+ languages via mostly **rule-based** grapheme→IPA maps plus context-sensitive pre-/post-processing rewrite rules — not trained statistical models — because most of its target orthographies are already close to phonemic. [aclanthology.org/L18-1429.pdf](https://aclanthology.org/L18-1429.pdf).
- **Phonetisaurus** (Novak et al.) uses joint n-gram models in a WFST framework, which requires an existing pronunciation dictionary to train on — data the target field-language population (previously unwritten languages, FieldWorks/LibLCM's audience) typically does not have. [researchgate.net/publication/283905667](https://www.researchgate.net/publication/283905667_Phonetisaurus_Exploring_grapheme-to-phoneme_conversion_with_joint_n-gram_models_in_the_WFST_framework).
- **g2p-seq2seq**/neural multilingual G2P approaches similarly need training data per language, or a multilingual model trained across many languages for reasonable zero-shot transfer — again a data-availability mismatch for single-field-language deployments.
- **Gi2Pi** ("Rule-based, index-preserving grapheme-to-phoneme," ComputEL 2022 — the ACL venue specifically for endangered/under-resourced language computational methods) is explicitly rule-based and designed for the language-documentation context. **I could not extract the PDF's text** (extraction failed) — I only have title/venue-level confirmation that a rule-based, non-trained G2P approach is the norm specifically targeted at this population, not the paper's own stated justification in its own words. [aclanthology.org/2022.computel-1.7.pdf](https://aclanthology.org/2022.computel-1.7.pdf).
- **When is G2P unnecessary at all?** SIL's own orthography-design literature is the important finding here: shallow (phonemic) orthographies, where each phoneme is symbolized consistently and distinctly, are the default target for **newly designed orthographies for previously unwritten languages** — exactly PanGloss's target population via FieldWorks/LibLCM. Gary Simons, "Principles of Multidialectal Orthography Design" (SIL, [scholars.sil.org PDF](https://scholars.sil.org/sites/scholars/files/gary_f_simons/reprint/multidialectal_orthographies.pdf)) lists social acceptability, psycholinguistic acceptability, minimal ambiguity, simplicity, and phonemic-contrast/neutralization-across-dialects as the guiding principles — all pushing toward shallow/phonemic, not deep/etymological, spelling. A related SIL piece, "Orthography and Phonological Depth" ([sil.org/resources/archives/71517](https://www.sil.org/resources/archives/71517) — **I could not fetch this page directly, HTTP 403; the following is from a search-engine summary of it, not independently verified full text**), reportedly argues the practically-useful representation level is "the output of the lexical phonology" — i.e., roughly the underlying/lexical layer PanGloss's rule cascades already operate on. **Implication**: for most PanGloss-supported grammars, there is likely little-to-no grapheme/phoneme mismatch to correct in the first place — the digraph problem the plan's Phase 3 example ("ph"→"f") illustrates is a specifically *English* orthographic-depth problem, not a generic field-language one.

### 5. Orthographic variation vs. genuine error (Divvun/Giellatekno)

- Divvun (UiT Norway) and Giellatekno share the **same source files** — two-level morpho-phonological rule files and lexicon files — between their morphological analyzers and their spellcheckers; i.e., the speller is built from the same grammar artifact as the parser, not a separately hand-authored error-detection resource. [giellatekno.uit.no/publications/index.html](https://giellatekno.uit.no/publications/index.html), [github.com/giellalt/lang-sme](https://github.com/giellalt/lang-sme).
- Their pipeline layers a **Constraint Grammar** disambiguator on top of the finite-state morphological analysis for North Sámi, and the speller can add new dictionary readings for legally-formed (e.g. dynamically compounded) but previously-unseen words, using the grammar's own combinatorial rules to accept them rather than flag them as errors. [giellatekno.uit.no/text.en.html](https://giellatekno.uit.no/text.en.html), search-summary of [giellatekno.uit.no/publications/divvun.pdf](https://giellatekno.uit.no/publications/divvun.pdf) (**PDF unreadable via fetch in this environment — flagged, not independently verified beyond this summary**).
- **I could not find, or verify from a primary source, an explicit Divvun/Giellatekno statement distinguishing "normalization" (mapping known competing/dialectal spelling variants together) from "correction" (fixing genuine errors)** as a named, principled design distinction. Two direct PDF-fetch attempts against Divvun/Giellatekno sources failed to extract readable text. This should be reported as **searched for, not found/verified**, rather than assumed to exist. What *is* well-supported is the architectural principle — reuse the grammar's own compiled analyzer as the speller's substrate — which is exactly the "derive, don't hand-author" argument this research task is testing, independent of whether their normalization/correction distinction is explicit or informal.

### 6. Cascade architecture vs. unified weighted search

- **Hunspell's actual suggestion algorithm** (documented via Spylls, a from-source, tested reimplementation of Hunspell's real algorithm, used here as a primary-adjacent description of the original's behavior) is a three-stage cascade: (1) small structural edits (deletion/insertion/swap/keyboard-adjacent substitution) checked against the dictionary; (2) if that yields too few results, n-gram distance computed against the *entire* dictionary; (3) an optional Metaphone-like phonetic "PHONE" table fallback. Documented weaknesses, in Hunspell's/Spylls' own words: **score incomparability** ("if any good edits found, ngram suggestions wouldn't be used" — an ad hoc gate, not a principled joint ranking across stages with different units); **redundant work** (ngram and phonetic stages both scan the whole dictionary — real Hunspell folds them into one cycle purely to avoid double iteration, not because they're conceptually the same computation); and an explicit **simultaneous-error failure mode** (their own worked example: "quas-Afro-American" needs the whole-word match "Afro-American" delegated to a sub-search, i.e. a single word combining a real typo and a legitimate compound/lookup issue defeats the simple staged model). [spylls.readthedocs.io/en/latest/hunspell/algo_suggest.html](https://spylls.readthedocs.io/en/latest/hunspell/algo_suggest.html).
- **Norvig's spelling corrector** ([norvig.com/spell-correct.html](https://www.norvig.com/spell-correct.html), fetched and read directly — **primary source**): formally frames correction as Bayesian `argmax_c P(c)·P(w|c)`, but the actual implementation is a **cascade over edit-distance buckets** (known words at distance 0, then distance 1, then distance 2), using what Norvig himself calls a "trivial, flawed error model" that treats edit distance as a hard threshold rather than a smooth probability. Norvig explicitly states the resulting flaw: "all known words of edit distance 1 are infinitely more probable than known words of edit distance 2" in his implementation — i.e., a common word two edits away can never outrank a rare word one edit away, purely an artifact of the staged/bucketed architecture, not a property of true phonetic or orthographic similarity. This is a first-party admission, from a widely cited primary source, of exactly the score-incomparability problem the plan's Phase-1→2→3 fallback cascade risks reproducing.
- **Academic noisy-channel spelling correction** (Brill & Moore, "An Improved Error Model for Noisy Channel Spelling Correction," ACL 2000) generalizes single-character edit operations to arbitrary-length string-to-string substitutions `α→β` with learned probabilities, folding typo-style and phonetic-style confusions into **one** weighted channel model rather than staged edit-distance-then-phonetic-fallback stages. **I found this via search summary only and did not extract/verify the full text or reported numbers** — cite with that caveat. [dl.acm.org/doi/pdf/10.3115/1075218.1075255](https://dl.acm.org/doi/pdf/10.3115/1075218.1075255).
- **General argument** (well-supported by the above, not just my own opinion): a "try exact/edit-distance first, fall back to phonetic index only on total miss" cascade breaks down specifically on inputs containing **both** a typo and a sound-alike substitution in the same word, because whichever stage runs first either exits early with a poor answer or the later stage's input (already corrupted by the earlier mismatch) no longer phonetically hashes to the right bucket. A single composed weighted search — one substitution-cost function covering both keyboard-adjacency and phonological similarity, run once — avoids the incomparable-score-across-stages problem entirely, at the cost of a larger single search space. This is the direction Brill & Moore, HFST's weighted composition, and (implicitly) Norvig's own stated regret all point toward.

## Consequences for PanGloss

**Verdict: revise Phase 3 substantially — replace the hand-authored English G2P + Soundex-style hash with a substitution-cost function derived mechanically from each grammar's own `CharDefTable`/`SymbolBits` feature lanes, and fold it into the same weighted search as Phases 1–2 rather than gating it behind a "zero structural matches" fallback.**

1. **Drop the hand-authored English G2P compiler (Step 3.1) as a *general* mechanism.** PanGloss's target languages, via FieldWorks/LibLCM, are predominantly ones with orthographies deliberately designed to be shallow/phonemic (SIL's own orthography-design literature — Simons, `scholars.sil.org`, and the (unverified-beyond-summary) SIL "Orthography and Phonological Depth" piece — states this is the standard goal for previously unwritten languages). The plan's own worked example, `"ph"→"f"`, is a symptom of English's specifically *deep* orthography, not a generic field-language problem. Building a general G2P layer for grammars whose orthography is already near-1:1 with `CharDefTable` segments is solving a problem most of these grammars don't have. **This is well-supported, not speculative**: it follows from (a) the orthography-design literature and (b) the fact that PanGloss already has, per grammar, the authoritative orthography↔segment mapping in `CharDefTable`'s `representations`/`representations_nfd` (`rust/crates/pg-grammar/src/chardef.rs:97-107`) — there is no need to re-derive a phoneme mapping the grammar's loader has already computed.

2. **Replace the Soundex-style inverse hash (Step 3.2–3.3) with a substitution-cost matrix derived from `unif_closure`/`feature_lanes`.** `CharDefTable::unif_closure` (`chardef.rs:126-136, 198-223`) already computes, per grammar, exactly the "which segments can satisfy the same natural-class constraint" adjacency that a hand-authored letter-grouping (Editex's `{c,k,q}`) or hash bucket (Soundex's 6-way consonant grouping) is a crude, English-specific approximation of — and it's already correct for whatever grammar is loaded, not just English. Two designs, in increasing sophistication, both well-precedented:
   - **Cheap/first pass**: treat `unif_closure` membership as a binary substitution-cost gate (cost 0 or 1) — structurally identical to Editex's letter-group scheme (Zobel & Dart 1996), but the groups come from the grammar's authored feature system instead of a hand-picked English table.
   - **Refined pass**: compute a graded cost as Hamming (or weighted-Hamming) distance directly over `feature_lanes` — this is exactly PanPhon's (Mortensen et al. 2016) feature-edit-distance and ALINE's (Kondrak 2000) weighted-feature model, except the feature table is the grammar's own authored inventory rather than a universal cross-language IPA table. This is arguably *more* principled than PanPhon/ALINE for any given supported language, since it uses the actual distinctions that grammar's author encoded (voicing, place, manner, etc., as XML-authored), not a generic approximation.

3. **Restructure the cascade itself, not just Phase 3's internals.** The "Phase 1 → Phase 2 → Phase 3-as-fallback-on-total-miss" architecture is the same shape Hunspell and Norvig's corrector use, and both have documented, first-party-acknowledged failure modes: score incomparability across stages (Norvig's own words: a common word two edits away can never beat a rare word one edit away) and failure on inputs with two simultaneous error types (Hunspell's own worked example). Brill & Moore's noisy-channel generalization and HFST's weighted composition both point the same direction: fold keyboard-distance cost (Phase 2) and phonological-similarity cost (revised Phase 3) into **one** substitution-cost function used by **one** weighted search over the deletion transducer (Phase 1), rather than three sequential stages with a hard gate between them. This handles the case the plan's own architecture cannot — a word with both a fat-finger typo and a sound-alike confusion in the same token.

4. **Be explicit, in whatever supersedes this plan, about which part is invention vs. precedent.** The pieces are well-supported individually: cascade-of-FSTs phonology (Kaplan & Kay 1994) is exactly what `pg-rules`'s cascade/rewrite modules already implement; feature-derived (not hashed) substitution cost is exactly PanPhon/ALINE's approach; composing an error/edit transducer with a lexicon-aware transducer is exactly what Oflazer 1996 and HFST's weighted composition describe (though I could not independently verify either primary text beyond search summaries — flagged above). But "use *this grammar's own* natural-class structure, rather than a universal or hand-authored one, as the substitution-cost source" and "run typo correction through the rule cascade's existing `analyze` direction as a generate-and-test step" are **not things I found already published** — they are a reasoned extension PanGloss would be making, not a citation-backed guarantee of success. Treat them as a design bet worth taking (the architectural ingredients already exist in-repo and the adjacent literature is consistent with the idea), not as "the literature already solved this for us."

5. **Do not build a general Divvun-style normalization-vs-correction layer on unverified grounds.** I could not confirm from a primary source exactly how Divvun/Giellatekno distinguish known-variant normalization from genuine-error correction; if PanGloss wants that specific design pattern, it needs its own follow-up investigation (e.g., reading their actual speller source/config, not just publications) rather than citing this report for it.
