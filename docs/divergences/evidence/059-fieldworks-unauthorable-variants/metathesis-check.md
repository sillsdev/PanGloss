# Metathesis authorability and HermitCrab check

_Real-engine run of 2026-10-08 (lane `metathesis-check`). The case directories it links (`cases/final/...`) hold the synthetic projects and engine output; they were not committed. The alpha-variable and bad-index projects are attached to LT-22826 and LT-22827._

Run date: 2026-10-08. All projects and words are synthetic. Evidence is under [`cases/final`](cases/final/).

## Disposition

The standard FieldWorks metathesis editor cannot create an iteration context inside the switch groups, and its controls do not provide an alpha-variable authoring path. In the actual LibLCM probe, iteration and sequence contexts were rejected by the metathesis structural-description collection; a low-level alpha-constrained rule could be saved, but HCLoader failed before producing HC XML. Those are `NOT AUTHORABLE` on the FieldWorks-to-HC path.

A bad switch index can be persisted by directly calling `UpdateStrucChange` with an out-of-range index. HCLoader then exits successfully, emits malformed HC XML with a dangling switch ID, and reports no diagnostic. Machine cannot load that state. The FieldWorks editor does not expose switch indices as editable values; its source derives them from formula-row edits, so this case is a persisted-corruption probe, not a demonstrated ordinary UI action.

For the product question, this evidence does not demonstrate a normally editor-authored rule that reaches any of these fast-path refusals. Iteration and alpha variables have no metathesis formula-editor path, and the bad index required low-level API mutation. Saved project data still reaches concrete failure boundaries: alpha constraints stop HCLoader, while an out-of-range index produces malformed HC XML that Machine cannot load.

For the optional/repeated cases, the actual HCLoader-exported control grammar is rule-free, so it does **not** test the intended metathesis. Machine generates all lexical roots unchanged in those exports; `ap` (and `app` for repetition) has zero analyses, while the identity forms have one. This matches that exported control grammar and fails the hand-derived intended rule. Separate parser-only XML files insert the refused shape and show that Machine rejects it before synthesis or parsing. Their XML is explicitly not represented as HCLoader output.

The actual rule-free control analyses were: optional, `ap: 0`, `a: 1`, `ta: 1`, `pa: 1`; repeated, `ap: 0`, `app: 0`, `ta: 1`, `ppa: 1`. The successful `parse-hc` control runs report no diagnostics, no word exceptions, and live/projected count agreement. On the parser-only optional/repeated runs, `roots` and `words` are empty because `Morpher` construction fails first. Alpha parser-only runs likewise return empty roots/words and a load error. Bad-index runs fail before words in both direct-XML and live-project paths.

The optional/repeated runtime exception occurs while Machine builds the analysis-side Morpher, so no forward-synthesis call is reached; the synthesis rule spec has the same switch-group `CastToConstraints` call in source. Thus the intended C# synthesis outputs are unavailable, rather than observed mismatches from a successfully loaded grammar.

For alpha, the actual low-level LCM state has `C={p,t,b,d}` and a shared `voc` constraint on both contexts. Both inserted switch directions were saved. HCLoader's `LoadMetathesisRule` calls `LoadPatternNode` without a variable dictionary; the simple-context path then indexes that null dictionary in `GetVariables`. The parser-only HC file declares the referenced alpha ID on a regular rule (its legal DTD location), then refers to it from the metathesis contexts. The HC loader still supplies an empty variable map to metathesis, producing the recorded `KeyNotFoundException`.

For bad-index, the low-level saved project records `leftSwitchIndex=0`, `rightSwitchIndex=99`, `leftSwitchLimit=99`, `rightSwitchLimit=2` over `[p,a]`. HCLoader did not refuse or warn; the HC file is present at `cases/final/bad-index-ltr/export/Probe.hc.xml` and `.../bad-index-rtl/export/Probe.hc.xml`. The `parse-hc` process captured the unhandled live `Morpher` exception but did not exit within the 45-second bound; the runner stopped it and recorded exit 124. The separate bounded `forward` harness returns the XML ID-reference error immediately. No word analyses were produced in either path.

## Authorability evidence and limits

- `cases/final/optional-{ltr,rtl}/authoring.json` and `repeated-{ltr,rtl}/authoring.json` record both failed additions: `PhIterationContext` and a `PhSequenceContext` wrapper cannot convert to `IPhSimpleContext`. The draft rule was removed before save; `persistedMetathesisRule` is false. The installed FieldWorks editor source supports this boundary: `FieldWorks/Src/LexText/Morphology/MetaRuleFormulaControl.cs:56-62` offers phoneme, natural-class, feature-class and boundary choices; `:402-427` inserts only `IPhSimpleContext` rows into `StrucDescOS`.
- For alpha, `MetaRuleFormulaControl` has no `RuleInsertType.Variable` option. Its feature-class chooser supplies a natural-class feature structure; `MetaRuleFormulaVc.cs:83-86` returns `-1` from `GetVarIndex`. I did not automate the FieldWorks GUI. The result is a source-level UI capability check plus a real saved LibLCM counterexample, not a screenshot or click-through test.
- Surprise during setup: the projector's initial `author` output declared `C={p,t,b,d}` in its source grammar, but the resulting `.fwdata` had an empty `PhNCSegments` membership. I corrected C in the alpha projects through a separate saved LibLCM operation and reprojected the clean parser basis. The final alpha evidence and hand derivation use `C={p,t,b,d}`; the earlier export remains at `cases/final/alpha-ltr/parser-basis/export/` and is not used for those results.
- The bad-index state was deliberately made through the low-level LibLCM API. `MetaRuleFormulaControl.cs:432-458` computes insertion positions from selected formula rows, `:423-427` calls `UpdateStrucChange` on insertion, and `:466-467` delegates deletion index updates to the context-delete side effect. There is no UI index field. Whether some unrelated editing sequence can corrupt an index was not exercised.
- Source mechanism checks: `FieldWorks/Src/LexText/ParserCore/HCLoader.cs:2103-2150` builds metathesis switch groups and calls the pattern loader without a variable map; `:2745-2772` indexes the supplied dictionary for each feature constraint. `machine/src/SIL.Machine.Morphology.HermitCrab/PhonologicalRules/AnalysisMetathesisRuleSpec.cs:20-52` casts switch-group children to constraints; `XmlLanguageLoader.cs:826-850` passes an empty variable dictionary for metathesis.
- The supplied `wild-variants.md` UNC path was inaccessible from this Windows session (access denied; WSL returned `E_ACCESSDENIED`). This report uses the shapes and refusal labels stated in the request and does not claim to have checked that background file.
- PanGloss itself was not run. The user supplied the PanGloss refusal labels; this experiment establishes FieldWorks/HCLoader authorability and installed Machine behavior for those shapes. XAMPLE output files were produced by `project`, but the native XAMPLE parser was not run.
