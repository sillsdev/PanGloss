# CLI compile error JSON

When `pangloss parse`, `batch`, or another command loads a grammar that cannot compile, it exits nonzero and emits one JSON object on a stderr line. `pangloss import` uses the same shape when import provenance contains fatal source issues; it refuses to write the snapshot. That line has no `pangloss <command>:` prefix. Input I/O and command usage errors remain text. Consumers should select the JSON line whose `status` is `compile_error`, since stderr can also carry progress messages.

```json
{"schema_version":1,"status":"compile_error","path":"sample.fwdata","message":"FieldWorks project cannot be converted to HC without semantic loss","issues":[{"code":"grammar.environment.unresolved","kind":"invalidSource","object_guid":"00000000-0000-0000-0000-000000000042","object_kind":"MoForm","field":"PhoneEnv","text":"environment does not resolve","advice":"In Lexicon > Lexicon Edit, inspect Allomorphs > Environments; in Grammar > Environments, inspect String Representation. Restore the intended environment or reselect it only if the reference is stale.","fatal":true}]}
```

`schema_version` versions this error shape separately from grammar-health. `code` is a stable diagnostic identifier. `kind` is the conversion issue class (`invalidSource`, `unrepresentableForHc`, etc.); early loader failures use `xml`, `semantic`, `unsupported`, `duplicate_representation`, or `unsegmentable_boundary` and code `grammar.compile.failed`. `object_kind` is the FieldWorks class name. `object_guid` and `field` are null when unavailable. `text` contains the authored environment expression when the issue identifies an environment; otherwise it contains the issue description. `advice` comes from the shared diagnostic catalog. `fatal` distinguishes the issues that prevent compilation from other collected findings. Do not assume each source appears once: the inventory can report an object and its attachments separately. Human text may change; use codes and identities for decisions.

`pangloss grammar-health <input> [<output.json>]` writes its existing version 4 report even when compilation is refused. Fatal conversion issues become error findings, with source subjects and owned advice; early loader failures use `grammar.compile.failed`. The command still exits nonzero if error findings exist. Checks that require a compiled grammar run only after successful compilation. Input I/O and snapshot decoding failures remain command errors.

Invalid environment expressions on usable roots and ordinary literal affixes produce `grammar.environment.invalid` warnings and follow FieldWorks' handling: roots omit invalid restrictions while keeping valid ones; ordinary affixes add one unrestricted pass when any environment is invalid, alongside valid passes. Infixes require at least one valid position environment; an infix with no valid position is skipped. Missing references and unrelated fatal conversion issues retain their refusals. Fix the expression in Grammar > Environments or its attachment in Lexicon > Lexicon Edit > Allomorphs > Environments.

The CLI does not persist a compiled HC grammar between invocations. Every parse/batch/grammar-health invocation imports and compiles its source again. Batch shares a grammar and morpher within one process; `--cache` stores statistics rather than a compiled grammar. `.pgpack` and FST publication are separate explicit workflows. This lane does not change caching.
