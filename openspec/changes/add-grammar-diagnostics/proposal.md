## Why

PanGloss is about to onboard on the order of 6000 real grammars, and today there is no
first-class, repeatable way to answer the two questions that decide whether a grammar is
healthy: **is it correct** (does every word get the right gloss, and does it match the C#
HermitCrab reference) and **is it going to be pathological** (which HC mechanism blows up
compile time or FST state count, and how slow is per-word parsing). The evidence we have is
scattered across one-off examples (`worst_words.rs`, `precision_bench.rs`, the
`dead-end-census` skill) and ad-hoc `pangloss batch` runs. We need one command we can point at
any grammar — dropped in an `incoming/` folder or given by path — that produces a standard
diagnostic report, so a slow or wrong grammar is caught on our machine before it becomes a
linguist's fire.

## What Changes

- **New `pangloss diagnose` subcommand** (Rust, in `pg-cli`) that loads a grammar
  (`.xml`/`.json`/`.fwdata`, via the existing `load_grammar` dispatch), runs its word list
  through **both** engines (default `Morpher` and `--engine=foma` propose→confirm), and emits a
  structured `report.json` plus a `glosses.tsv` (every word → its gloss).
- **Per-word timing distribution** in the report: total word count and p50 / p95 / p99 / worst /
  mean per-word parse time, per engine.
- **Per-mechanism compile profile**: counts, compile time, and FST size (states/arcs) attributed
  to each HC mechanism category (phonological rewrite rules subtyped, affix templates, α-variable
  tuple expansion, MPR/POS partition groups, compounding, strata, char-def tables), plus the
  **state-explosion curve** (composed-net size after each compose-fold step) to spot pathological
  compilation. This reuses the already-staged compile (`compile_and_compose_rules`' one-rule-at-a-
  time fold; `emit`'s per-template lexc build) and the existing `ComposeBudget`/emit counters.
- **Optional deep per-word debug** (`--debug`, foma path): proposed-candidate count, confirmed
  count, and cascade-dead-end signal per word — the `dead-end-census` axis, so the report points
  at the precision lever for a slow grammar.
- **Optional full HermitCrab run** (`--full`): a small new command in the `machine` submodule's
  `SIL.Machine.Morphology.HermitCrab.Tool` runs the C# reference over the same words and emits
  comparable per-word timing + gloss; the runner diffs Rust vs C# for word→gloss **parity** and
  comparative timing. Off by default (Rust-only is the fast path).
- **`incoming/<lang>/` convention** (gitignored) and one PowerShell entry point
  `scripts/diagnose.ps1` (`<lang>` | `-All` | `-Project <path>` `[-Full] [-Debug]`) that sweeps
  every language present, invokes the Rust core and (optionally) the C# harness, and renders a
  human-readable `report.md`.
- **CI guard**: a job that runs `diagnose` on a tiny committed synthetic grammar generated by
  `pg-grammar-gen`, so the pipeline itself cannot bit-rot. Real-language corpora stay gitignored
  and are never run in CI.
- **Repo skill** `.claude/skills/grammar-diagnostic/` documenting when to run the pipeline and how
  to read its output (sibling to, and feeder of, `dead-end-census`).

No production parsing behavior changes: all instrumentation is behind the diagnostic path/flags;
the deployment engine stays Rust and byte-for-byte unchanged.

## Capabilities

### New Capabilities
- `grammar-diagnostics`: a standard, repeatable per-grammar diagnostic — one entry point over an
  `incoming/` folder or a project path — producing per-word timing distributions, a per-mechanism
  compile profile with a state-explosion curve, a word→gloss dump, optional deep propose→confirm
  debug, and an optional C#-HermitCrab parity + comparative-timing run, plus its CI guard and repo
  skill.

## Impact

- **New code**: `pg-cli` `diagnose` subcommand + a diagnostics module (report model, timing
  aggregation, compile-profile attribution); diagnostic-only timers/counters threaded through
  `pg-foma` compile (`emit`, `replace::compile_and_compose_rules`) behind a capture hook — no
  change to the non-diagnostic compile path.
- **C# (harness only, not deployment)**: a new stats/timing subcommand in
  `machine/src/SIL.Machine.Morphology.HermitCrab.Tool` reusing its existing batch TSV protocol.
- **Scripts / convention**: `scripts/diagnose.ps1`; `incoming/` (gitignored, with a committed
  `README.md` + tiny fixture); `.gitignore` entry.
- **CI**: one new job in `.github/workflows/rust-ci.yml` (or a sibling workflow) running the
  synthetic-fixture diagnostic.
- **Dependencies**: `dotnet` (already present, v10) is required only for `--full`; the default
  path has no new dependency.
- **Docs**: cross-references `docs/fst-plan/synthetic-stress-grammar-plan.md` (construct matrix +
  blowup-vector catalog V1–V7), the `dead-end-census` skill, `docs/fst-plan/foma-fst-plan.md`
  (`--word-timeout-ms`), and the
  `machine/conformance/PROTOCOL.md` TSV contract.
