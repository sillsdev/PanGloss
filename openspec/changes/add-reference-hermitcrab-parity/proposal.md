# Run the C# founding oracle on demand, to author ground truth

**Shrunk from a standing harness to an on-demand procedure (2026-08-08).** The original scope — a new
C# `gloss-batch` command, a `--full` diagnostic comparison mode, two-pass delta reruns with bounded
tracing, and machine-readable FieldWorks investigation handoffs — is withdrawn. What replaces it is
small enough to state in a paragraph, and most of it already exists upstream.

## Why the original scope went away

Three facts, each checked rather than assumed:

- **The oracle already authored the ground truth.** `machine/conformance/PROTOCOL.md` states that
  every fixture's expected output was generated by running the C# implementation. Consuming those
  fixtures needs no harness at all.
- **The adapter already exists.** `machine/conformance/adapters/hc-dotnet-wrapper.sh` implements the
  3-argument `batch <grammar> <words> <out.tsv>` contract, resolves its own paths, and accepts a
  prebuilt `hc.dll`. This change's premise — that HermitCrab.Tool's `-i/-s` CLI shape needs a new
  command written to bridge it — is obsolete; the wrapper is the bridge.
- **The protocol does not privilege C#.** It says so directly: HermitCrab is the first implementer,
  not a privileged consumer, and the Rust CLI arrived at the same `batch` contract independently.

## Why it is not retired outright

New conformance fixtures are authored the TDD way — write a synthetic grammar the system gets wrong,
then fix the system. Something has to say what the correct answer is. If `pangloss` defines it, the
fixture cannot catch us being wrong about what HermitCrab does, and a self-certifying fixture defeats
the purpose of a conformance suite. So the oracle stays reachable — as a procedure, not a
standing harness.

## What Changes

- Document running the existing upstream adapter to generate ground truth for a NEW fixture, as a
  deliberate on-demand act on one machine. **Landed in
  `.claude/skills/conformance-grammars/SKILL.md`** — including the part that was missing and is the
  reason people fall back to `pangloss`: the submodule is sparse-checked-out to
  `machine/conformance` only, so `machine/src` (350MB, where the oracle lives) is absent by default,
  and widening/narrowing is opposite depending on whether a given worktree is sparse or full.
- Keep the existing rule that a fixture authored against `pangloss` must say so, and never claim
  C#-oracle provenance that was not actually run.

## Non-goals

No new C# command. No standing comparison harness. No per-worktree dotnet setup. No FieldWorks
handoff format. No two-pass delta tracing. If a real divergence needs investigating, that is a
one-off run, and the evidence rules in `docs/` already govern it.

## Impact

Documentation and procedure only. No Rust, no C#, no build change. The C# side remains upstream
source in the `machine` submodule and is not distributed with PanGloss Runtime or the SDK.
